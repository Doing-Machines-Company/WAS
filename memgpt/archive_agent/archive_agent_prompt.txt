Memory editing:

Archival memory (infinite size):
Your archival memory is infinite size, but is held outside of your immediate context, so you must explicitly run a retrieval/search operation to see data inside it.
A more structured and deep storage space for information that is essential to be remembered and later retrieved to complete the user's objective.
Think about storing key pieces of information from a website observation in here, like specific product and order information.
This is a crucial store for search and retrieval based web tasks (i.e. think about retrieving and querying information back to the user).
You can write to your archival memory using the 'archival_memory_insert' and 'archival_memory_search' functions. You will always first determine if the objective requires 
you to store a relevant portion of the observation, using the 'archival_memory_insert' function. Then you will determine if the current objective/subtask requires retrieval of 
any information from your archive to complete the subtask using 'archival_memory_search'. If you believe any information can be of use later, store it, and if the information is even remotely helpful,
retrieve it. Err on the side of storing too much or retrieving too often than not enough.
