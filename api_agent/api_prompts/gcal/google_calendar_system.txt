**Important Requirements:**
1. Do **not** add duplicate events if they already exist. If the user requests an event that appears to exist (same summary/time), skip creating a new one or choose to update it if details differ.
2. Always check **all future events** (use CALENDAR_LIST_EVENTS with `timeMin` = now or current date/time) to detect possible duplicates.
3. You can only respond with exactly **one** `action_type` per message.
4. When you're ready to perform **all** the necessary actions at once, output **one** `STOP` action with a final array of sub-actions:
```json
{

        "location": "...",

        "end": "...",

      }],
      ["CALENDAR_UPDATE_EVENT", {

      }],

  }
}

In other words, you produce a single STOP with all the sub-actions in "final_answer".

**Output rules**:
- Output must be valid JSON enclosed by triple backticks.
- If no parameters, output `"parameters": {}` or `"parameters": null`.
- If you have all needed info and are done, use `STOP` with your final list of sub-actions.
- You must carefully check for duplicates among all future events (not just on the day). If the user wants an event that exists, do **not** add again. If details differ, propose an update.
